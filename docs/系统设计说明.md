# 系统设计说明（论文第 3–4 章素材，可直接改写使用）

> 本文档描述代码的实际实现，供系统设计文档使用。
> 所有结构、字段名、算法参数都与仓库代码一致，可逐条核对。

## 〇、数据集与类别（实际配置）

| 类别 | 中文 | 数据来源 | 样本数 |
| --- | --- | --- | --- |
| `listening` | 听讲 | SCB-Dataset「听讲」子集（纯图片） | 2,451 |
| `raising_hand` | 举手 | SCB-Dataset5 子集 A（hand-raising） | 13,388 |
| `reading` | 阅读 | SCB-Dataset5 子集 A（read） | 23,737 |
| `writing` | 书写 | SCB-Dataset5 子集 A（write） | 9,694 |
| `desk` | 低头/转头 | SCB-Dataset5「BowTurnHead」子集 | 15,298 |

- 合计 **64,568 张行为图像**，划分为 train 40,043 / val 11,684 / test 12,841（种子 42）；
- **检测框 → 分类样本**：以框中心外扩 6% 裁剪，丢弃边长 < 32 像素的框，共得到 62,117 个裁剪样本；
- **划分单位是“场景”**：SCB 连续帧共享场景前缀（如 `0001xxx`），同场景帧只进一个集合；
  这一条是真实数据特有的坑——同一张课堂照片里常同时标注多种行为，若按类别分别划分，
  同一场景会在 A 类进训练、B 类进测试（实测出现 116 个来源跨集合），必须**全局按来源分配一次**。

## 一、总体架构

```
            ┌────────────── 数据层 ──────────────┐
 原始视频/图片 → 抽帧(1fps, 去重) → labels.csv → 按来源分层划分 → splits.json
                                       │
                              ┌────────┴────────┐
                              │   模型层         │
                              │ HOG+SVM 基线     │
                              │ ResNet18 三种训练 │ → 混淆矩阵 / 指标 / 模型产物
                              │  （冻结/从头/微调）│
                              └────────┬────────┘
                                       │
            ┌────────────── 应用层 ─────┴──────────────────────┐
  视频 → 逐帧分类 → 时序平滑 → 行为时间线 + 课堂统计
                                       │
                    教学建议知识库(FAISS) → Prompt → 本地 Qwen3.5-0.8B → 观察报告
                                       │
            └────────── FastAPI /analyze → 网页展示（时间线/统计/报告/依据）──┘
```

## 二、数据结构定义（实现一致）

**labels.csv**：`file,label,source,frame_idx,split`
`source` 是划分的分组键（一段视频 / 一张原图 / 一位出镜者）。

**splits.json**：`seed, val_ratio, test_ratio, unit="source", counts, sources, assignment, leaked_sources`

**models/\<tag\>/config.json**：
`tag, backbone, head, classes, class_to_idx, image_size, freeze_backbone, best_epoch, best_val_macro_f1, test_accuracy, test_macro_f1`

**outputs/时间线_\<tag\>.json**：
`times[], raw[], raw_confidence[], smoothed[], stats{}`

**outputs/统计_\<tag\>.json**：
`帧数, 时长秒, 各类帧数, 各类占比, 抬头率, 低头率, 举手次数, 手机次数, 低头时长秒, 事件数, 事件列表[], 平均置信度, 模型, 输入, 采样间隔秒, 平滑前后一致率`

**outputs/报告_\<tag\>.json**：
`tag, stats_source, stats, retrieved_tips[], report, citation_check{无效编号, 是否漏引用}, prompt, model`

**GET /progress 返回**：`{running, stage_index, stage, detail, percent, elapsed, stages[9], finished, error}`

**POST /analyze 返回**：
`video, tag, stats, timeline_image, timeline{times, raw, smoothed}, report, tips[], stats_text, duration_ms`

## 三、关键算法

**1. 抽帧与去重**：按 `step = round(源fps / 目标fps)` 取帧；相邻帧灰度平均绝对差 < 3.0 视为重复丢弃
（`src/prepare_frames.py`）。1 fps 时一节 45 分钟课约 2700 帧。

**2. 按来源分层划分**：对每个类别，把来源随机打乱（`seed=42`）后先填测试集、再填验证集、其余进训练集；
保证任何来源的帧只出现在一个集合里。脚本会断言并打印“来源泄漏检查”
（`src/make_splits.py`）——这是防止“用相邻帧测试自己”的关键设计。

**3. HOG + SVM 基线**：灰度缩放到 64×128，`cv2.HOGDescriptor` 提取 3780 维特征，
`StandardScaler` 标准化后送入 `SVC(kernel='rbf', C=10, class_weight='balanced')`
（`src/baseline_hog_svm.py`）。基线的作用是：先有一个能算混淆矩阵的对照，再谈深度学习收益。

**4. ResNet18 三种训练方式**（`src/train_cnn.py`，同一份数据、同一测试集）：

| 方式 | 命令要点 | 可训练参数 | 测试准确率 / 宏 F1 |
| --- | --- | --- | --- |
| 冻结主干（只训分类头） | `--backbone hf`（默认冻结） | 2,565 | 0.4810 / 0.5795 |
| **不用预训练（从头训练 12 轮）** | `--backbone scratch --no-freeze --lr 1e-3` | 11,179,077 | 0.6274 / 0.7082 |
| **预训练 + 全网络微调（最终方案）** | `--backbone hf --no-freeze --lr 3e-4` | 11,179,077 | **0.7142 / 0.7812** |

实现细节：从 `microsoft/resnet-18` 载入 ImageNet 权重，把最后的 `Linear(512→1000)` 换成
`Linear(512→5)`（5 个类别）；AdamW + CosineAnnealing + fp16 混合精度；
按**验证集宏 F1** 保存最优轮次。`--backbone scratch` 等价于 `resnet18(weights=None)`，
即结构相同但权重随机初始化。

**5. 时序平滑**（本系统的核心后处理）：取长度 5 的滑窗，用**真实类别概率**加权投票得到平滑标签；
再把长度小于 2 帧的过短事件并入前一段类别（`smooth_predictions`）。
效果（真实数据演示视频）：事件数 10 → 4，平均片段 2.5 → 6.25 帧，平滑前后一致率 80%。

**6. 课堂统计**：抬头率 = (听讲 + 举手) / 总帧数；低头率 = (阅读 + 书写 + 低头转头) / 总帧数；
举手次数按“事件数”而非帧数统计；低头时长按采样间隔换算为秒（`build_stats`）。

**7. 教学建议检索**：24 条自建教学建议用 `bge-small-zh` 编码为 512 维归一化向量，
建 `IndexFlatIP` 索引，按内积（即余弦相似度）取 Top-3（`src/build_index.py`）。

**8. 报告生成**：System Prompt 给出 5 条硬约束——只依据统计与检索到的建议、数字必须来自统计、
建议必须用 `[资料N]` 标注、统计未涉及的写“本次统计未涉及”、给出数据使用的边界。
用本地 Qwen3.5-0.8B 非思考模式贪心解码（`do_sample=False`），
生成后做引用规范化与有效性检查（`src/report_llm.py`）。

**9. 数字忠实度自动检查**：抽出报告中的所有数字，逐个在“统计 + 引用的教学建议”文本里查找，
计算可溯源比例（`src/ablation.py::number_fidelity`）。
注意它会把“模型自行做加法”（26.7%+6.7%=33.4%）和序数标为不可溯源，因此只能粗筛，最终仍需人工核对。

**10. 识别前/后对比图**（演示用）：从视频里**随机抽 6 帧**，原帧直接另存为“识别前”，
再用 PIL + 黑体在帧上叠加绿色标签条（预测类别 + 置信度 + 平滑后类别 + 帧号/秒数）另存为“识别后”，
前端两列并排展示（`web/app.py::make_comparison_images`）。中文用项目内 `assets/fonts/simhei.ttf` 渲染。

## 四、接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 演示页面 |
| GET | `/examples` | 可选视频列表（`raw/` 训练素材 + `demo/` 演示视频） |
| GET | `/model-info` | 模型配置与各模型指标 |
| POST | `/analyze` | 入参 `{video, fps, with_report}`，返回时间线、统计、报告、**识别前/后对比图**与依据 |
| GET | `/progress` | 返回 Pipeline 当前阶段（9 个阶段：抽帧→分类→平滑→统计→对比图→检索→报告→整理），前端每 400 ms 轮询 |
| GET | `/docs` | FastAPI 自动生成的接口文档 |
| GET | `/outputs/*` | 静态访问生成的图表 |

服务默认监听 `127.0.0.1:8002`（避开常见的 8000 / 8001 端口），单进程串行推理，
首次请求才加载大模型，避免与 Notebook 争显存。

## 五、实现中的难点与解决

| 难点 | 现象 | 解决 |
| --- | --- | --- |
| 数据泄漏 | 随机按帧划分时，同段视频的相邻帧同时进训练和测试，指标虚高 | 改为**全局按来源分层划分**（同一场景只进一个集合）；真实数据上抓到 116 例跨类别泄漏后修正 |
| 预训练是否必要 | 需要验证"不用预训练行不行" | 增加 `--backbone scratch` 从头训练对照：12 轮仍未收敛，宏 F1 比微调低 **0.0730** |
| 演示不够直观 | 需要"看得见识别前后差异、看得见跑到哪一步" | 右侧 9 阶段 Pipeline 进度面板（`/progress` 轮询）+ 随机抽帧的识别前/后对比图 |
| 模型输出抖动 | 同一秒内预测在“听讲/低头”之间跳变，时间线不可读 | 滑窗概率加权投票 + 短事件合并，并把平滑前后做成消融实验 |
| 属性缺失幻觉 | 资料未提停车场却回答“有/没有停车场” | 报告环节改为“统计驱动 + 检索增强 + 引用编号”，并做数字忠实度检查 |
| 环境坑 1 | OpenCV 5.0 移除了 `HOGDescriptor`，基线直接报错 | 依赖固定 `opencv-python-headless<5`（4.14） |
| 环境坑 2 | 训练 `loss.backward()` 报 “does not require grad” | 评估用 `torch.no_grad()`、训练不加 `inference_mode` |
| 环境坑 3 | 加载大模型时 triton 找不到 C 编译器 | 在 import torch 前设 `TORCH_DISABLE_NATIVE_JIT=1` |
| 换数据集 | 旧指标与新指标混在同一张对比表里 | `compare_models.py` 检测测试样本数不一致并告警；`run_all.sh` 支持 `CLEAN=1` |

## 六、可扩展方向（论文“不足与展望”用）

1. 多机位融合：目前单个机位只覆盖前排若干学生，多机位可覆盖整间教室；
2. 时序模型升级：把逐帧分类换成 TSN / SlowFast 之类的视频模型，直接建模行为片段；
3. 跨课型迁移：实验课与理论课的行为分布不同，可用域适应或按课型分别建模；
4. 报告个性化：把教师历史偏好纳入检索，让建议更贴合该教师的课堂；
5. 隐私增强：人脸模糊、端侧推理与数据最小化采集。
