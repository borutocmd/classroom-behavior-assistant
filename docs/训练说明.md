> 这份文档解决三件事：**原模型是什么、在哪**；**怎么自己训练一遍**；**训练时该看什么**。
> 适合自己跑一遍加深理解，也方便随时复现。

## 一、原模型（预训练权重）在哪

| 项 | 内容 |
| --- | --- |
| 模型名 | `microsoft/resnet-18`（HuggingFace 上的 ImageNet-1k 预训练 ResNet-18） |
| 结构 | ResNet-18：11,179,077 个参数，原始输出 1000 类 |
| 本机缓存位置 | **`~/project/models_cache/resnet18/`**（WSL 里，45 MB） |
| 文件 | `config.json`、`model.safetensors`、`preprocessor_config.json` |

WSL 里查看：

```bash
ls -la ~/project/models_cache/resnet18/
cat ~/project/models_cache/resnet18/config.json | head -20
```

⚠️ 注意：**原模型是 1000 类的图像分类模型**，我们需要的是"5 类课堂行为"。
`train_cnn.py` 做的是**迁移学习**：加载原模型 → 把最后的全连接层换成 5 类 →
用我们的课堂数据继续训练。原模型的卷积层特征（边缘、纹理、形状）被保留下来。

## 二、怎么自己训练（三条命令）

先准备好环境（只需一次）：

```bash
cd /path/to/classroom-behavior-assistant
PY=/home/muli/project/NLP_lab/.venv/bin/python
$PY tests/smoke_test.py        # 环境自检，应全部通过
$PY tools/fetch_backbone.py    # 确认原模型就位（已存在会跳过）
```

### ① 快速试训（1 分钟，先看现象）

```bash
$PY src/train_cnn.py --backbone hf --no-freeze --limit 2000 --epochs 2 --batch-size 48 --tag trial
```

只取 2000 条训练样本跑 2 轮，**实测 37 秒**。适合第一次上手：看它会打印什么、
产物落在哪里。跑完可以删掉：`rm -rf models/trial_limit2000 outputs/*trial_limit2000*`

### ② 冻结主干（只训分类头，约 4 分钟）

```bash
$PY src/train_cnn.py --backbone hf --epochs 5 --batch-size 64 --workers 4
```

可训练参数只有 **2,565** 个（占 0.02%）。实测：每轮约 45 秒，
最终测试 **准确率 0.4810 / 宏 F1 0.5795**。

### ③ 全网络微调（我们的最终方案，约 7 分钟）

```bash
$PY src/train_cnn.py --backbone hf --no-freeze --lr 3e-4 --epochs 6 --batch-size 48 --workers 4
```

11,179,077 个参数全部训练。实测：每轮约 63 秒，
最终测试 **准确率 0.7142 / 宏 F1 0.7812**（论文里用的就是这个）。

### ④ 不用预训练：从头训练 ResNet18（消融对照，约 13 分钟）

```bash
$PY src/train_cnn.py --backbone scratch --no-freeze --lr 1e-3 --epochs 12 \
    --batch-size 48 --workers 4 --tag scratch
```

`--backbone scratch` 表示**不加载任何预训练权重**（`resnet18(weights=None)`），
网络结构与 `microsoft/resnet-18` 完全一致，只是权重随机初始化。
从头训练需要更大的学习率（用 `--lr 1e-3`）和更多轮次。

实测：12 轮、每轮约 65 秒，最终测试 **准确率 0.6274 / 宏 F1 0.7082**。
训练记录（`runs/scratch/history.json`）显示验证宏 F1 仍在缓慢上升
（第 11 轮 0.6956 最优，第 12 轮 0.6765），**说明还没收敛**。

**三种训练方式的对比（同一份数据、同一个测试集 12,841 张）**：

| 训练方式 | 轮数 | 可训练参数 | 测试准确率 | 测试宏 F1 |
| --- | --- | --- | --- | --- |
| 冻结主干（只训分类头） | 5 | 2,565 | 0.4810 | 0.5795 |
| **不用预训练（从头训练）** | 12 | 11,179,077 | 0.6274 | 0.7082 |
| **预训练 + 全网络微调** | 6 | 11,179,077 | **0.7142** | **0.7812** |

结论：
1. 只训分类头会欠拟合，解冻主干带来 **+0.2017** 宏 F1；
2. 即使从头训练到 12 轮，仍比预训练微调低 **0.0730** 宏 F1，而且：
   - 从头训练需要更多轮次（12 轮仍未收敛）→ 训练时间更长；
   - 本数据集只有 4 万张训练图，属于中小规模，预训练学到的通用视觉特征确实有用。
3. 换句话说：**预训练不是"锦上添花"，而是这个数据规模下"能用"的前提**。

想边看进度边训：加 `--progress`（显示每个 batch 的进度条）。

## 三、训练时该看什么

每轮会打印一行，格式是：

```
  第  5/6 轮  训练损失 0.3153 训练准确率 0.8702 | 验证损失 0.7305 验证准确率 0.7378 验证宏F1 0.7785
```

判断标准：

| 现象 | 含义 | 怎么办 |
| --- | --- | --- |
| 训练准确率一直上不去（如卡在 0.62） | **欠拟合**：模型容量没用上 | 解冻主干（去掉 `--no-freeze` 的反面：加上它） |
| 训练准确率还在涨、验证宏 F1 开始回落 | **过拟合** | 已经自动处理：只保存验证宏 F1 最好的那一轮 |
| 损失是 NaN 或报显存不足 | batch 太大 | `--batch-size 32` 或 `--image-size 160` |
| 每轮很慢 | 数据 IO 或线程不够 | 加 `--workers 4`，数据放 WSL（本项目已如此） |

**我们真实跑出来的两条曲线对比**（这就是"为什么必须微调"的证据）：

| | 冻结主干 | 全网络微调 |
| --- | --- | --- |
| 第 1 轮 验证宏 F1 | 0.5227 | 0.7174 |
| 最后一轮 | 0.5330（几乎没动） | 0.7750（第 5 轮 0.7785 最优） |
| 测试集 | 0.5795 | **0.7812** |

曲线图：`outputs/训练曲线_hf_frozen.png`、`outputs/训练曲线_hf_finetune.png`
（左图损失、右图验证准确率与宏 F1）

## 四、参数说明

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--backbone hf` | hf | 用 `microsoft/resnet-18` 预训练权重 |
| `--backbone scratch` | — | 不用预训练，从头训练（做个对照，效果会差很多） |
| `--no-freeze` | 关 | 解冻主干做全网络微调；不加则冻结主干只训分类头 |
| `--epochs` | 15 | 训练轮数；实测 6 轮就够（第 6 轮验证已回落） |
| `--batch-size` | 32 | 显存不够就调小 |
| `--lr` | 1e-3 / 3e-4 | 冻结模式用 1e-3，微调模式用 3e-4（`--lr` 可覆盖） |
| `--image-size` | 224 | 输入边长 |
| `--limit N` | 0 | 只取 N 条训练样本做快速试训 |
| `--progress` | 关 | 每个 batch 显示进度条 |
| `--tag` | 自动 | 产物目录名（`models/<tag>/`），默认 `hf_frozen` / `hf_finetune` |

训练完自动做的事：**在测试集（12,841 张）上评估 → 画混淆矩阵 → 写指标 json → 画训练曲线 → 保存模型**。

产物位置：

```
models/<tag>/config.json     记录 backbone / 类别 / 最优轮次 / 测试指标
models/<tag>/model.pt        模型权重（约 44 MB）
outputs/指标_<tag>.json      准确率、宏 F1、逐类 precision/recall/F1、混淆矩阵数值
outputs/混淆矩阵_<tag>.png   计数与归一化两张图
outputs/训练曲线_<tag>.png   损失与验证指标曲线
~/project/classroom_data/runs/<tag>/history.json   每轮明细（含耗时）
```

## 五、常见问题

**Q：训练要联网吗？**
不用。原模型已经缓存在 `~/project/models_cache/`，训练全程离线。

**Q：会不会把之前训好的模型覆盖掉？**
会。同一个 `--tag` 会覆盖 `models/<tag>/`。想保留旧的就换个 tag：
`--tag my_experiment`。

**Q：能换类别吗？**
可以。改 `config.py` 里的 `CLASSES`（以及 `CLASS_NAMES_CN`），重新跑
`prepare_frames.py → make_splits.py → train_cnn.py`。模型头会自动变成对应的类别数。
（我们就是这么做 6 类 → 5 类的：手机类没有真实数据，去掉了。）

**Q：显存不够怎么办？**
先降 `--batch-size` 到 32 或 16；还不行就 `--image-size 160`。8 GB 显存跑 224×224、
batch 48 是够的（我们的实测配置）。

**Q：想复现论文里的数字，跑哪条命令？**
就是上面第 ③ 条，`--epochs 6 --batch-size 48 --lr 3e-4`，期望结果
**测试准确率 0.7142 / 宏 F1 0.7812**。硬件相同、随机种子固定（`SEED=42`），结果应当接近。
